# System-design prompts and coding exercises for LLM-agent / AI-engineering roles (2025–2026)

Scope note: notes compiled 2026-10-27. Sources are mostly 2025–2026 interview-prep guides, candidate-report aggregators, and a few engineering posts. Hello Interview's own AI-design content, interviewing.io, ByteByteGo newsletter issues and Reddit/Blind threads could not be retrieved (see Gaps). Company attributions below are candidate-reported via third-party sites, not company disclosures.

## Key Question 1: Which agent/LLM system-design prompts recur across prep sources and company guides?

### Takeaway
A small set of prompts recurs almost everywhere: (1) customer-support agent that calls tools and escalates, (2) enterprise/RAG document Q&A with permissions and citations, (3) AI coding assistant / code-review agent, (4) LLM inference/serving API with batching and streaming, (5) agent harness + eval platform. Agent-product companies (Sierra, Decagon, Scale) ask the support-agent prompt in their own domain; labs (OpenAI, Anthropic) lean toward serving/batching infra and "harness + eval" prompts; Meta asks coding-agent prompts.

## Key Question 2: What rubric / answer structure do sources give for an LLM system-design round, and how does it differ from classic distributed-systems design?

### Takeaway
Every source keeps the classic skeleton (clarify, estimate, high-level, deep dive, trade-offs) but adds four LLM-specific grading axes: bounding what the system may do (action/permission boundary), closing the loop with evaluation, cost/latency realism per model call, and naming failure modes (hallucination, injection, tool misuse) before being asked. The biggest stated difference: a model answer can be wrong while the service reports success, so evaluation and observability are core, not optional.

### Cited Findings

**Structures**
- KDnuggets 7-step structure: (1) Clarify data sources, privacy, latency budget, tolerance for factual errors, scale, freshness, API vs self-hosted; (2) Estimate tokens/sec, context size, embedding volume, cost/call, peak QPS; (3) Sketch default flow: input layer → safety/PII layer → orchestrator → retrieval (vector DB + reranker) → routed model → post-LLM guardrails → response streaming → observability; (4) Deep dive one or two components (RAG strategy, prompt design, caching, model tiering); (5) Trade-offs (latency vs quality, RAG vs fine-tuning, cost ceilings, fallback models); (6) Failure modes + observability (hallucinations, prompt injection, provider outages, embedding drift, multi-tenant isolation) and how each is detected; (7) Evolution (A/B prompt testing, feedback loops, eval gates before release, gradual model migration). "The most commonly reported failure is jumping to a solution before clarifying requirements." — [KDnuggets](https://www.kdnuggets.com/how-to-answer-ai-system-design-interview-questions)
- DataTalks.Club nine-step practice answer: restate product (user, task, risk, source of truth, action boundary); propose simplest baseline; draw request path (UI/API, auth, retrieval/tools, context builder, model, validator, storage, response); RAG details (ingestion, chunking, metadata, permissions, embeddings, search, reranking, citations, reindexing); tools/agents (tool permissions, typed inputs, mocked + integration tests, stop conditions, human approval); separate retrieval/answer/safety/product-metric evaluation; red-team cases (prompt injection, data leakage, unsafe output, tool misuse); latency/cost levers (model choice, token budgets, caching, streaming, batching, retries, fallbacks); observability, rollout, rollback, ownership — [DataTalks.Club](https://datatalksclub.github.io/podwiki/wiki/llm-system-design-interview/)
- DataTalks clarifying questions to ask before drawing: who is the user; what task; what source of truth; what happens when uncertain; "Can the system only advise, or can it call tools and change state?"; latency/cost/privacy/safety limits — [DataTalks.Club](https://datatalksclub.github.io/podwiki/wiki/llm-system-design-interview/)
- Grigorev field guide five-step timing: problem framing 5–10 min, high-level architecture 10–15, deep dive 20–30, trade-offs and failure modes 10–15, conclusion; four recurring patterns: RAG, feedback/reinforcement loops, hallucination mitigation, scalability/cost optimization — [ai-engineering-field-guide](https://github.com/alexeygrigorev/ai-engineering-field-guide/blob/main/interview/questions/04-ai-system-design.md)
- DesignGurus "five forms" of AI design question: design a known ML product; design a GenAI product (e.g. support assistant); add AI to an existing system ("Design whatever AI feature you'd like" is this form in disguise); design an agent that takes actions (e.g. issues small refunds — focus is control: what it may touch, how many steps, when a person must approve); critique/scale an existing AI design, ranking problems by harm. Recommended opening: classify the form, confirm the lane, state the plan before drawing — [DesignGurus](https://www.designgurus.io/course-play/grokking-the-ai-system-design-interview/doc/how-ai-system-design-shows-up-in-interviews)

**Rubric items**
- DesignGurus four things to cover in every form: requirements with concrete numbers (resolution rate, latency, cost per conversation); the complete loop feeding quality signals back into evaluation and the next model version; cost and latency realism for every model call; "failure honesty" — naming how the model fails and the fallback before being asked — [DesignGurus](https://www.designgurus.io/course-play/grokking-the-ai-system-design-interview/doc/how-ai-system-design-shows-up-in-interviews)
- Grigorev senior/staff expectations: "reasoning across uncertainty" (keeping the system predictable despite unpredictable outputs), trade-off fluency (retrieval speed vs context length, GPU cost vs latency), communication clarity; mid-level needs only a reasonable high-level architecture. Common mistakes: skipping requirements, treating the LLM as source of truth, ignoring failure modes and evaluation, naming tools without reasoning, ignoring cost/latency, ignoring safety (prompt injection, data leakage, unsafe tool execution), putting control flow in prompts, choosing agents without a need for autonomy — [ai-engineering-field-guide](https://github.com/alexeygrigorev/ai-engineering-field-guide/blob/main/interview/questions/04-ai-system-design.md)
- PromptLayer whiteboard rubric (agent decomposition task — draw flow chart, pick a model per step, optionally draft a prompt): clear decomposition into sub-tasks; logical flow between agent steps; error handling and edge cases; prompt structure for each component; justification of agent boundaries — [PromptLayer](https://blog.promptlayer.com/the-agentic-system-design-interview-how-to-evaluate-ai-engineers/)
- Aced sample rubric for the Scale AI insurance-claims agent: scope inputs/outputs (approve, deny, escalate); retrieve relevant policy clauses; human routing above confidence or dollar thresholds; cost control via caching, tight top-k retrieval, model routing, per-claim token budgets; evaluate retrieval and decisions separately; log decisions with citations. Questions "reward guardrails, cost control, and a human fallback" — [Aced](https://www.aced.io/blog/ai-engineer-interview-questions)
- Aced sample rubric for the Anthropic single-GPU batching prompt: trade throughput vs latency; dynamic batching with max batch size and max wait window; padding/bucketing by sequence length; backpressure; continuous batching for token generation — [Aced](https://www.aced.io/blog/ai-engineer-interview-questions)
- LangChain guide warning: "a generic logging-platform answer that ignores LLM specifics will not score well"; LLM-specific concerns = token-level streaming, non-determinism, cost attribution — [LangChain guide](https://www.techinterview.org/companies/langchain/?format=md)
- techinterview.org 2026 rubric additions: verifying AI-derived numbers (pasting an unchecked AI estimate is a negative signal); knowing when AI helps (capacity math, diagram rendering) vs not (novel architectural reasoning); awareness of AI-era infra patterns even at non-AI companies; articulating AI-system trade-offs (managed vs self-hosted embeddings, Pinecone vs pgvector vs Vespa). Items that matter more now: clarification reflex, independent reasoning, narrating reasoning — [techinterview.org](https://www.techinterview.org/post/3233474919/ai-in-system-design-interviews-2026/?format=md)

**Differences from classic system design**
- "A model's answer can be wrong while the service reports success, so the loop must close"; illustrative figures: a model call may cost ~10,000x a database read and take ~1,000x longer; little credit for math inside the model, newest model names, or Kafka-vs-Kinesis brand comparisons — [DesignGurus](https://www.designgurus.io/course-play/grokking-the-ai-system-design-interview/doc/how-ai-system-design-shows-up-in-interviews)
- Core format unchanged (vague prompt → scoping → architecture → deep dive → trade-offs), but "the deep dive is harder, not easier" because AI handles breadth; diagrams may be AI-rendered so the verbal description is graded — [techinterview.org](https://www.techinterview.org/post/3233474919/ai-in-system-design-interviews-2026/?format=md)
- PromptLayer (interviewer-side view): candidates graded on model choice, prompt structure, context design, evaluation metrics, currency of knowledge, and "try and check" experimentation; red flag = generic textbook answers — [PromptLayer](https://blog.promptlayer.com/the-agentic-system-design-interview-how-to-evaluate-ai-engineers/)
- Educative: AI incidents (hallucination spikes, safety bypasses, cost explosions) "may have no 500 errors", so kill switches, throttles and fast rollback replace classic error-rate alerting; safety is a system-wide invariant not a preprocessing filter — [Educative](https://www.educative.io/blog/ai-system-design-interview-questions)
- The 2026 ML-engineer round: "the most common ML system design problem in 2026 is some variant of 'design an LLM-based system for X'", judged on the standard rubric (requirements, capacity, data flow, evaluation) plus LLM-specific architectural choices — [techinterview.org ML post](https://www.techinterview.org/post/3233474925/ml-engineer-interview-post-llm-era/?format=md)
- Classic distributed-systems problems "remain the most-asked and should come first", with LLM inference/RAG/agents added afterward — [techinterview.org](https://www.techinterview.org/post/3233474919/ai-in-system-design-interviews-2026/?format=md)

### Inferences
- A reusable "LLM design round" template: boundary (what the model may do + who approves) → request path → RAG/tool specifics → eval stack (retrieval, answer, safety, product) → cost/latency levers → failure modes + observability → rollout/rollback. Stating the failure modes unprompted is the differentiator most sources mention.
- Interviewers at agent companies grade product judgment (what to ship first, what to escalate) alongside architecture, unlike classic rounds.

### Gaps
- No source publishes an actual company scoring sheet; all rubrics are inferred by prep sites or by interviewer-side blog authors (PromptLayer is the only first-person interviewer source found).

## Key Question 3: What follow-up probes are typical?

### Takeaway
Probes cluster into: evaluation (offline vs online, judge calibration, what "resolved" means), tool-call failures (model doesn't call tool / malformed call / loops forever), cost bounding (routing, caching, token budgets), retry-safety/idempotency (duplicate side effects), streaming (SSE vs WebSockets, resuming dropped streams), prompt injection (retrieved content as untrusted, tool allowlists), versioning/rollout (prompt and model versioning, shadow/canary, rollback), and state/multi-tenancy (permissions, isolation, context bounding).

### Cited Findings

**Evaluation**
- Decagon probes: define "resolved" (solved, not just deflected); offline test sets from past tickets, LLM-as-judge, human review, live metrics (resolution rate, escalation rate, CSAT); "catching quality regressions before a prompt or model change ships"; offline vs live evaluation — [Decagon guide](https://www.techinterview.org/companies/decagon-interview-guide/?format=md)
- LangChain domain round: evaluation metrics = final-answer correctness, tool-selection accuracy, trajectory match against a reference path; judge calibration = validating LLM-as-judge scores against human labels before trusting them — [LangChain guide](https://www.techinterview.org/companies/langchain/?format=md)
- KDnuggets eval probe: offline evals using LLM-as-judge calibrated against ground truth; online metrics such as faithfulness, context recall, answer relevance — [KDnuggets](https://www.kdnuggets.com/how-to-answer-ai-system-design-interview-questions)
- Callsphere RAG probes: chunking trade-offs, embedding selection (incl. Matryoshka), Recall@K/MRR/NDCG and faithfulness metrics, multimodal docs; agent probes: agent evaluation metrics, context window management, prompt injection defenses, "refusal behavior under user pressure (Anthropic)"; support-assistant probes: multi-turn state tracking, hallucination rate, escalation quality, resolution rate, CSAT correlation — [Callsphere](https://callsphere.ai/blog/ai-system-design-interview-questions-2026-faang-openai-anthropic)
- LinkedIn prep lists cited in search: "how would you evaluate an agent beyond checking its final answer?"; "how would you separately evaluate retrieval and generation?"; "what happens when a tool fails or the agent loops forever?"; chunk size and overlap choice — [LinkedIn prep post](https://au.linkedin.com/in/alexowji)
- DataTalks: test agents "by checking outcomes and tool parameters rather than exact reasoning paths" — [DataTalks guide](https://datatalks.club/podwiki/guides/llm-system-design-interview/)

**Model not calling the tool / malformed calls / loops**
- LangChain domain round: agent control flow = state handling, tool selection, "recovery from malformed tool calls, and a stopping condition"; trade-off ReAct vs native function-calling vs explicit state machines (LangGraph-style) and when to pick each — [LangChain guide](https://www.techinterview.org/companies/langchain/?format=md)
- Decagon prep areas: failure modes such as prompt injection, tool misuse, and runaway loops; probes on behavior for ambiguous or out-of-scope requests and guardrails against wrong or irreversible actions — [Decagon guide](https://www.techinterview.org/companies/decagon-interview-guide/?format=md)
- Inspect (UK AISI) ReAct implementation note: some loops terminate when the model stops calling tools, but "models will unintentionally stop calling tools", so an explicit submit tool is used — [Inspect ReAct](https://inspect.aisi.org.uk/react-agent.html)
- DataTalks: tools/agents require tool permissions, typed inputs, stop conditions, human approval — [DataTalks.Club](https://datatalksclub.github.io/podwiki/wiki/llm-system-design-interview/)

**Bounding cost**
- KDnuggets: model routing (routine to cheaper models), claimed 40–70% savings since 60–80% of agent requests are routine; levers = routing, semantic caching, prompt compression, streaming — [KDnuggets](https://www.kdnuggets.com/how-to-answer-ai-system-design-interview-questions)
- Aced Scale AI rubric: caching, tight top-k retrieval, model routing, per-claim token budgets — [Aced](https://www.aced.io/blog/ai-engineer-interview-questions)
- Educative: size GPU pools by tokens/sec not requests/sec; "token economics" as the capacity model; graceful degradation = shorter outputs, smaller fallback models, cached responses, disabled optional features; probes "How do you estimate tokens per second? What is your degradation path when capacity runs out?" — [Educative](https://www.educative.io/blog/ai-system-design-interview-questions)
- Tian Pan: retry storms during incidents can account for 30–60% of unexpected monthly inference spend; example $50 batch job costing $200 after three retries — [tianpan.co](https://tianpan.co/blog/2026-04-20-idempotency-llm-pipelines)

**Idempotency / retry safety**
- Two retry categories: transient reliability retries (work happened, response lost → return cached original result) vs sampling retries (output failed validation → new generation with the prior error appended to the prompt and a distinct idempotency key). Agents retrying a timed-out tool call may duplicate side effects (repeated Slack messages, double charges). Patterns: scope keys to logical units with external side effects, not per inference call; prefer read-only tools, push writes to end of workflow; log intent with idempotency key before irreversible actions; saga pattern with completion records distinguishing "ran" from "succeeded"; acknowledge webhooks then process async with queue-level dedup — [tianpan.co](https://tianpan.co/blog/2026-04-20-idempotency-llm-pipelines)
- Callsphere agent components include "budget limits, undo log", "action classification", sandboxing — [Callsphere](https://callsphere.ai/blog/ai-system-design-interview-questions-2026-faang-openai-anthropic)

**Streaming**
- Educative explicit interviewer question SSE vs WebSockets: SSE for one-way token streaming, proxy/CDN friendly; WebSockets for bidirectional control (tool calls, cancellation, progress). Probes: "How do you resume a dropped stream? How do heartbeats and backpressure work? How are partial responses attributed in logs?" — [Educative](https://www.educative.io/blog/ai-system-design-interview-questions)
- SystemDesignHandbook OpenAI guide: ask whether token-by-token delivery via server-sent events is required — [SystemDesignHandbook](https://www.systemdesignhandbook.com/guides/openai-system-design-interview/)
- DataTalks: stream "only if it doesn't hide unsafe intermediate output" — [DataTalks.Club](https://datatalksclub.github.io/podwiki/wiki/llm-system-design-interview/)

**Prompt injection / safety**
- Educative: instructions and data share one channel; layered defenses = immutable system prompts, sanitized and provenance-tracked retrieved context, schema-constrained and allowlisted tool calls, output validation; probes on continuous eval, red-teaming, metrics-driven safety gates — [Educative](https://www.educative.io/blog/ai-system-design-interview-questions)
- LangChain guide: prompt-injection defenses, input/output guardrails, tool allowlisting, output validation, "treating retrieved content as untrusted" — [LangChain guide](https://www.techinterview.org/companies/langchain/?format=md)
- DataTalks: name the threat model first (injection from users and from retrieved documents), add controls outside the model; red-team cases for injection, data leakage, unsafe output, tool misuse; permission leaks across tenants/roles — [DataTalks.Club](https://datatalksclub.github.io/podwiki/wiki/llm-system-design-interview/)
- Meta reported probe: keeping a coding agent from leaking private code through training and at inference — [Dev.to](https://dev.to/adityajha2005/what-openai-anthropic-mistral-and-meta-actually-ask-in-ai-engineer-interviews-2adk)

**Prompt/model versioning and rollout**
- Educative: versioned models, gated deployments, rollback, compatibility testing across prompts/tools/models; probes "How do shadow deployments and canaries work? How fast can you roll back?"; "silent regressions from model, prompt, or tool changes" — [Educative](https://www.educative.io/blog/ai-system-design-interview-questions)
- KDnuggets evolution step: A/B prompt testing, feedback loops, eval gates before release, gradual model migration — [KDnuggets](https://www.kdnuggets.com/how-to-answer-ai-system-design-interview-questions)

**Other recurring probes**

- Inference-service probes: how the system degrades under pressure; routing data-residency-constrained tenants; which metrics trigger scaling; who gets priority during overload; when to stop accepting work — [Educative](https://www.educative.io/blog/ai-system-design-interview-questions)
- RAG/orchestration probes: how to bound context size, cache retrieval, replay decisions; stale or conflicting documents; when retrieval adds noise — [Educative](https://www.educative.io/blog/ai-system-design-interview-questions); [Decagon guide](https://www.techinterview.org/companies/decagon-interview-guide/?format=md)
- Latency baseline cited: frontier-model response ~3–5 seconds — [KDnuggets](https://www.kdnuggets.com/how-to-answer-ai-system-design-interview-questions)

### Inferences
- Probes mirror production incident classes (loops, duplicate side effects, injection, silent regression); candidates who frame answers as "detect → contain → roll back" match what Educative and Decagon describe.

### Gaps

## Key Question 4: What coding exercises are reported for agent roles, and what do graders look for?

### Takeaway
Reported exercises are practical rather than algorithmic: write an agent loop given tools + LLM, process a token stream into structured events, build an eval harness over a dataset, implement async retry with backoff/timeouts, batch LLM API calls, parse tool-call schemas, and take-homes that build a support/document-QA agent with evaluation metrics. Graders look for a working feature that survives edge cases, tests, clean error handling, and the ability to defend design choices in a follow-up.

### Cited Findings

**Live coding exercises**
- LangChain (60-min, medium-hard): agent loop (given tools, an LLM, a question → execute tool calls, return final answer); stream processor (token-level streaming → structured events); trace tree construction from a stream of log events; evaluation harness running a chain/agent over a dataset with programmatic and LLM-based metrics; graph/tree problems with LLM twists (dependency resolution for tool chains, trace-span aggregation) — [LangChain guide](https://www.techinterview.org/companies/langchain/?format=md)
- Decagon (60-min pair): practical TypeScript/Python with a concurrency or LLM-tooling angle: parsing a tool-call schema; handling a streaming model response; retrying failed API calls with backoff; coordinating concurrent requests. "Interviewers weigh clean structure and sensible error handling above clever tricks." Prep: one LLM API (tool schemas, structured output, streaming), ReAct-style loops, RAG, eval frameworks — [Decagon guide](https://www.techinterview.org/companies/decagon-interview-guide/?format=md)
- Sierra: async exponential retry mechanism with timeouts and backoff added to an existing Python codebase; detect circular references among spreadsheet cell dependencies (graph traversal + optimization follow-up). Grading: "a working feature that holds up under edge cases. Handle empty inputs, malformed files, and large sets, and write at least one test." — [Aced](https://www.aced.io/blog/ai-engineer-interview-questions); [Aced Sierra guide](https://www.aced.io/guides/sierra-agent-engineer-interview)

## Key Question 5: What production-engineering topics do interviewers probe (async, streaming, timeouts/retries, rate limiting, caching incl. prompt caching, durable execution/checkpointing, tracing)?

### Takeaway
Production probes center on serving economics (batching, KV/prefix caching, tokens-per-second capacity), resilience (timeouts, backoff, backpressure, admission control, idempotent retries), state (checkpointing and human-in-the-loop resume), and observability (per-step traces with prompt hashes, model versions, tool traces, cost per request). Industry survey data show observability is near-universal in production agent teams while evals lag, which is why eval design is the discriminating probe.

### Cited Findings

**Async / concurrency / rate limiting**
- Decagon: coordinating concurrent requests; retrying failed API calls with backoff — [Decagon guide](https://www.techinterview.org/companies/decagon-interview-guide/?format=md)
- Sierra: async exponential retry with timeouts and backoff — [Aced](https://www.aced.io/blog/ai-engineer-interview-questions)
- Educative inference service: edge auth, quota enforcement, admission control, routing by tenant/model class/region; failure modes "cost blowups and noisy neighbors without admission control"; backpressure tied to SLOs; priority policy under load — [Educative](https://www.educative.io/blog/ai-system-design-interview-questions)
- techinterview.org inference API components: multi-tenant isolation, rate limiting, billing — [techinterview.org](https://www.techinterview.org/post/3233474919/ai-in-system-design-interviews-2026/?format=md)
- Grigorev field guide still lists a classic "rate limiter (global, per-user, distributed)" prompt for SWE lanes — [ai-engineering-field-guide](https://github.com/alexeygrigorev/ai-engineering-field-guide/blob/main/interview/questions/04-ai-system-design.md)

**Batching / caching / prompt caching**
- Continuous vs static batching, prefix caching, KV cache layer, speculative decoding, p99 tail latency, cost-per-query as probes for the ChatGPT-style service — [Callsphere](https://callsphere.ai/blog/ai-system-design-interview-questions-2026-faang-openai-anthropic)
- Educative: batching amortizes overhead, KV caching avoids recomputing attention, speculative decoding uses a draft model; failure modes KV caches exhausting memory, speculative decoding degrading on distribution shift, unbounded batching raising latency; probe "When does speculative decoding stop paying off?" — [Educative](https://www.educative.io/blog/ai-system-design-interview-questions)
- Anthropic batching rubric: dynamic batching with max batch size + max wait window, bucketing by sequence length, continuous batching — [Aced](https://www.aced.io/blog/ai-engineer-interview-questions)
- Semantic caching and prompt compression as cost levers — [KDnuggets](https://www.kdnuggets.com/how-to-answer-ai-system-design-interview-questions)
- Provider prompt/prefix/semantic caches "reduce cost but don't guarantee idempotent delivery"; caching must share keys with idempotency logic or retries bypass the cache; semantic dedup of proposed tool calls (cosine ~0.9 near-identical, ~0.85 equivalent intent; reported 20–45% hit rates; funnel exact match → embeddings → LLM verification, <~50 ms lookup) — [tianpan.co](https://tianpan.co/blog/2026-04-20-idempotency-llm-pipelines)

**Streaming**
- SSE vs WebSockets, resume on dropped stream, heartbeats, backpressure, partial-response attribution in logs — [Educative](https://www.educative.io/blog/ai-system-design-interview-questions)
- Token streaming via SSE as a component in the conversational-service design — [Callsphere](https://callsphere.ai/blog/ai-system-design-interview-questions-2026-faang-openai-anthropic)
- Stream processor coding exercise (token-level streaming → structured events) — [LangChain guide](https://www.techinterview.org/companies/langchain/?format=md)

**Durable execution / checkpointing / state**
- LangChain: state management and checkpointing ("persisting agent state so workflows can resume"); human-in-the-loop pausing for review/interruption; LangGraph persistence layer prompt — [LangChain guide](https://www.techinterview.org/companies/langchain/?format=md)
- Grigorev list: distributed job queue for 100k+ GPU training jobs with preemption and checkpointing; ChatGPT-style cross-conversation memory — [ai-engineering-field-guide](https://github.com/alexeygrigorev/ai-engineering-field-guide/blob/main/interview/questions/04-ai-system-design.md)
- Callsphere agent components: planner, task queue/DAG, executor, memory manager (short/long/working), undo log, budget limits — [Callsphere](https://callsphere.ai/blog/ai-system-design-interview-questions-2026-faang-openai-anthropic)
- Saga pattern with completion records and compensating actions for multi-agent retries; "idempotency becomes a property of workflows, not just individual operations" — [tianpan.co](https://tianpan.co/blog/2026-04-20-idempotency-llm-pipelines)
- Inngest: each agent-loop iteration as a durable, retriable step with a max-iteration cap — [Inngest](https://www.inngest.com/docs/ai-patterns/agent-tool-loops)
- Agent gateway vs LLM gateway: LLM gateways unify provider calls with caching, logging, token tracking; agent gateways manage multi-step stateful tasks with tool governance, state management, policy enforcement, observability (TrueFoundry, updated Dec 2025) — [TrueFoundry](https://www.truefoundry.com/es/blog/top-agent-gateways)

**Tracing / observability**
- Signals to log: prompt hashes (not raw text), model versions, retrieval metadata, tool traces, safety decisions, latency, cost per request; probes on redaction, access control, retention, sampling — [Educative](https://www.educative.io/blog/ai-system-design-interview-questions); same list in [KDnuggets](https://www.kdnuggets.com/how-to-answer-ai-system-design-interview-questions)
- LangSmith-style trace ingest at 1B+ traces/day; sampling, retention, indexing for debug queries; cost attribution — [LangChain guide](https://www.techinterview.org/companies/langchain/?language=en&format=md)
- techinterview.org: "billing for long-running traces, debugging agent behavior" as agent-infra components — [techinterview.org](https://www.techinterview.org/post/3233474919/ai-in-system-design-interviews-2026/?format=md)
- LangChain State of Agent Engineering (1,340 responses, 18 Nov–2 Dec 2025): 57% have agents in production; 32% cite quality as a top barrier; ~89% have observability vs 52% evals; among production teams observability 94% and full per-step tracing 71.5% (62% overall); offline evals 52.4%, online evals 37.3% — [LangChain report](https://langchain.com/state-of-agent-engineering); summarized by [KDnuggets](https://www.kdnuggets.com/the-state-of-agent-engineering-report-overview)
- Trace tree construction from a stream of log events as a coding exercise — [LangChain guide](https://www.techinterview.org/companies/langchain/?format=md)

**Incident response specific to AI systems**
- Hallucination spikes, safety bypasses, cost explosions "may have no 500 errors"; kill switches, traffic throttles, fast rollback; postmortems must consider prompt changes, distribution shift, upstream data — [Educative](https://www.educative.io/blog/ai-system-design-interview-questions)
- Recommended reading for infra prompts: engineering blogs from OpenAI, Anthropic, Cohere, Hugging Face, and public post-mortems from Cloudflare, Anthropic, OpenAI — [techinterview.org](https://www.techinterview.org/post/3233474919/ai-in-system-design-interviews-2026/?format=md)

### Inferences
- A production-readiness checklist that matches the probes: per-request budget (tokens, steps, wall-clock) → idempotency keys on side-effecting tools → checkpoint after each step → SSE with resumable offsets → per-step tracing with prompt hash + model version + cost → eval gate before prompt/model rollout → kill switch.
- Because observability is already common (89%) and evals are not (52%), interviewers get more signal from asking how a candidate evaluates than from asking what they log; this is consistent with Decagon and LangChain making eval design a dedicated round topic.

### Gaps
- No source names OpenTelemetry, Langfuse, or LangSmith as explicit interview vocabulary beyond the LangChain-company guide; tracing probes are described generically.
- "Prompt caching" as a provider feature (e.g., cache-control on prompt prefixes) is not mentioned by any interview-prep source; only generic prefix/semantic caching appears.
- No source gives numeric timeout/backoff policies interviewers expect; the Sierra exercise only specifies "exponential retry with timeouts and backoff".
