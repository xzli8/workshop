# Canonical knowledge taxonomy for building LLM agents (authoritative curricula, vendor guides, books; 2023–2026)

Research date: 2026-10-27. Primary sources fetched directly unless marked "(secondary)". Chapter/section names are copied from the sources; nothing is invented. Where a source could not be read in full (Google whitepapers, LLM Engineer's Handbook, Hello-Agents sub-sections) the gap is stated.

## Key Question 1: Chapter outlines and key points of each authoritative source

### Takeaway
Across 20+ sources the same skeleton recurs: (1) what an agent is / agent loop, (2) when to use one (workflow vs agent, simplest-thing-first), (3) building blocks: model + tools + instructions/prompt, (4) orchestration patterns incl. multi-agent, (5) memory/RAG/context engineering, (6) evaluation, (7) guardrails/safety/human-in-the-loop, (8) production: tracing, durable execution, deployment. 2025–2026 vendor material adds context engineering, tool design as its own discipline, evals (pass@k / pass^k), MCP, and durable/stateful execution as first-class topics.

### Cited Findings

#### 1A. Anthropic — "Building effective agents" (Dec 19, 2024; page now carries a note that tooling has changed since)
- Outline (in order): 01 What are agents? · 02 When (and when not) to use agents · 03 When and how to use frameworks · 04 Building blocks, workflows, and agents · 05 Combining and customizing these patterns · 06 Summary · Appendix 1: Agents in practice (A. Customer support, B. Coding agents) · Appendix 2: Prompt engineering your tools — [Anthropic](https://www.anthropic.com/engineering/building-effective-agents)
- Definitions: "agentic systems" is the umbrella; "Workflows are systems where LLMs and tools are orchestrated through predefined code paths"; agents are LLMs that "dynamically direct their own processes and tool usage" — [Anthropic](https://www.anthropic.com/engineering/building-effective-agents)
- When to use: find the simplest solution that works; agentic systems trade latency and cost for performance; workflows for predictable, well-defined tasks; agents for flexible, model-driven decisions at scale; "for many applications, optimizing single LLM calls with retrieval and in-context examples is enough" — [Anthropic](https://www.anthropic.com/engineering/building-effective-agents)
- Frameworks: start with LLM APIs directly; frameworks hide prompts/responses and make debugging harder; understand the underlying code — [Anthropic](https://www.anthropic.com/engineering/building-effective-agents)
- Building block = "augmented LLM" (retrieval, tools, memory). Five workflow patterns: prompt chaining, routing, parallelization (sectioning + voting), orchestrator-workers, evaluator-optimizer. Autonomous agents: loop on environmental feedback, can pause for human input, best for open-ended problems with unpredictable step counts; higher cost, compounding errors, test in sandboxes with guardrails — [Anthropic](https://www.anthropic.com/engineering/building-effective-agents)
- Three core principles: simplicity, transparency of planning steps, careful agent-computer interface (ACI) via tool docs and testing — [Anthropic](https://www.anthropic.com/engineering/building-effective-agents)
- Appendix 2 (tool prompt engineering): give the model room to think, use formats close to internet text, avoid formatting overhead; "poka-yoke" tools; example: requiring absolute file paths removed relative-path errors in the SWE-bench agent — [Anthropic](https://www.anthropic.com/engineering/building-effective-agents)

#### 1B. Anthropic — "Effective context engineering for AI agents" (Sep 29, 2025)
- Outline: 01 Context engineering vs. prompt engineering · 02 Why context engineering matters (context rot, attention budget) · 03 The anatomy of effective context (system prompts at the "right altitude", tools, examples) · 04 Context retrieval and agentic search (just-in-time retrieval, progressive disclosure, hybrid) · Context engineering for long-horizon tasks (compaction, structured note-taking, sub-agent architectures) · 05 Conclusion — [Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Key framings: context is a finite resource with diminishing returns ("context rot"); goal is "the smallest set of high-signal tokens"; system prompt altitude between brittle hard-coded logic and vague guidance; tools self-contained, token-efficient, minimally overlapping; few diverse canonical examples beat edge-case lists — [Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Agent defined as "LLMs autonomously using tools in a loop"; long-horizon technique choice: compaction for extended back-and-forth, note-taking for milestone-driven iterative work, multi-agent for parallel exploration — [Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

#### 1C. Anthropic — "Writing effective tools for agents — with agents" (Sep 11, 2025)
- Outline: 01 What is a tool? · 02 How to write tools (building a prototype; running an evaluation; analyzing results; collaborating with agents) · 03 Principles (choosing the right tools; namespacing; returning meaningful context; optimizing for token efficiency; prompt-engineering tool descriptions) · Looking ahead — [Anthropic](https://www.anthropic.com/engineering/writing-tools-for-agents)
- Key points: tools are "a contract between deterministic software and non-deterministic agents"; eval tasks need verifiable outcomes, track runtime/tool-call count/tokens/errors; consolidate multi-step ops into one tool, avoid overlapping tools; return names not UUIDs, offer response_format concise/detailed; paginate/filter/truncate (Claude Code caps tool responses at 25,000 tokens); error messages must be actionable; unambiguous parameter names (user_id not user) — [Anthropic](https://www.anthropic.com/engineering/writing-tools-for-agents)

#### 1F. OpenAI — "A practical guide to building agents" (PDF, 2025)
- Contents: What is an agent? · When should you build an agent? · Agent design foundations (Selecting your models; Defining tools; Configuring instructions; Orchestration: single-agent systems, when to consider multiple agents, multi-agent systems — manager pattern, decentralized pattern) · Guardrails (types; building guardrails; plan for human intervention) · Conclusion — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Definition: "Agents are systems that independently accomplish tasks on your behalf"; two characteristics: LLM manages workflow execution and decisions (recognizes completion, self-corrects, hands back on failure) and dynamically selects tools within guardrails; chatbots/single-turn/classifiers are not agents — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- When to build: complex decision-making, difficult-to-maintain rules, heavy reliance on unstructured data; otherwise "a deterministic solution may suffice" — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Foundations: three components model/tools/instructions; model selection = set up evals → hit accuracy target with best model → swap in smaller models for cost/latency; tool types data/action/orchestration (agents as tools); computer-use models for legacy systems without APIs; instruction best practices: use existing SOP docs, break down tasks, define clear actions, capture edge cases — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Orchestration: "maximize a single agent's capabilities first"; split when complex logic (many if-then branches) or tool overload (overlap, not count: some run >15 distinct tools, others struggle with <10 overlapping); manager (agents as tools, edges = tool calls) vs decentralized (handoffs transfer execution) — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Guardrails as layered defense: relevance classifier, safety classifier (jailbreak/prompt injection), PII filter, moderation, tool safeguards (risk rating low/med/high by read-only vs write, reversibility, permissions, financial impact), rules-based (blocklist, length limits, regex), output validation; human intervention triggers: exceeding failure thresholds and high-risk actions — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)

#### 1H. OpenAI Model Spec (version 2026-08-18)
- Top-level structure: Overview (red-line principles, general principles, specific risks, instructions and levels of authority) · Definitions · The chain of command · Stay in bounds · Seek the truth together · Do the best work · Use appropriate style · Under-18 principles — [OpenAI Model Spec](https://model-spec.openai.com/2026-08-18.html)
- Chain of command sections (all Root-level): Follow all applicable instructions · Respect the letter and spirit of instructions · No other objectives · Act within an agreed-upon scope of autonomy · Control and communicate side effects · Assume best intentions · Ignore untrusted data by default — [OpenAI Model Spec](https://model-spec.openai.com/2026-08-18.html)
- Authority levels: Root (Model Spec only, cannot be overridden) > System (OpenAI, via system messages) > Developer (API developer messages) > User > Guideline (implicitly overridable) > No Authority: "assistant and tool messages; quoted/untrusted text and multimodal data in other messages"; tool outputs are ignored as instructions "unless an applicable higher-level instruction delegates authority to it" — [OpenAI Model Spec](https://model-spec.openai.com/2026-08-18.html)
- Agentic rule: autonomy "must be bounded by a clear, mutually understood scope of autonomy" defining which sub-goals may be pursued, acceptable side effects (time, money, data, access), and when to pause for clarification/approval; scope can be built into product design or negotiated — [OpenAI Model Spec](https://model-spec.openai.com/2026-08-18.html)

### Inferences
- The 2024 sources (Weng, Google Agents, Anthropic BEA) organize around the agent's internal anatomy (planning / memory / tools / orchestration); the 2025–2026 sources (OpenAI guide, Anthropic follow-ups, LangChain, Hello-Agents) organize around the engineering lifecycle (build → evaluate → guard → deploy → monitor), with context engineering and tool design promoted to standalone chapters.
- Hello-Agents is the only curriculum that gives training (Agentic-RL, SFT→GRPO) and agent protocols (MCP/A2A/ANP) their own chapters; Berkeley's 2025 syllabi likewise lean to post-training/RL for agents, signalling that "how agentic models are trained" is becoming expected background even for application engineers.

## Key Question 3: Recurring design-decision framings

### Takeaway
The sources repeatedly frame the same decisions: workflow vs agent (simplest thing first), single vs multi-agent (maximize one agent first; split on logic complexity or tool overlap), LLM-driven vs code-driven control flow, how much to pre-load vs retrieve just-in-time, which grader and which metric (pass@k vs pass^k) to use, and when to escalate to humans or pause for approval.

### Cited Findings
- Workflow vs agent: Anthropic — use workflows for predictability, agents when model-driven flexibility is needed; "find the simplest solution possible" — [Anthropic](https://www.anthropic.com/engineering/building-effective-agents); OpenAI — build an agent only for complex decisions, unmaintainable rules, or unstructured data; else deterministic — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf); Ng frames "degrees of autonomy" — [DeepLearning.AI](https://www.deeplearning.ai/courses/agentic-ai/)
- LLM-driven vs code-driven orchestration: OpenAI SDK explicitly contrasts "orchestrating via LLM" (open-ended) and "via code" (deterministic, predictable cost/speed), and says to combine — [OpenAI Agents SDK](https://openai.github.io/openai-agents-python/multi_agent/); LangGraph "mixed control" in one graph — [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview); 12-factor "own your control flow" — [12-factor](https://github.com/humanlayer/12-factor-agents)
- Single vs multi-agent: OpenAI "maximize a single agent's capabilities first", split on complex logic or tool overload — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf); Anthropic: multi-agent only for high-value, parallelizable tasks (research yes, coding less so) given ~15× tokens — [Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system); manager (agents as tools) vs handoffs choice: use manager when one agent should own the final answer, handoff when the specialist should respond directly — [OpenAI Agents SDK](https://openai.github.io/openai-agents-python/multi_agent/)
- Framework vs no framework: Anthropic recommends starting with raw APIs and reducing abstraction layers for production — [Anthropic](https://www.anthropic.com/engineering/building-effective-agents); 12-factor "own your prompts", "own your context window" — [12-factor](https://github.com/humanlayer/12-factor-agents)
- Pre-load vs just-in-time context: Anthropic hybrid (preload for speed, explore as needed); choose compaction vs note-taking vs sub-agents by task shape — [Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents); 12-factor bonus "pre-fetch all the context you might need" — [12-factor](https://github.com/humanlayer/12-factor-agents); Claude SDK: start with agentic search, semantic search is faster but less accurate/transparent — [Claude blog](https://claude.com/blog/building-agents-with-the-claude-agent-sdk)
- Model selection: prototype with the most capable model, then swap smaller models where evals still pass — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf); Huyen "Model Build Versus Buy", "Navigate Public Benchmarks" — [aie-book ToC](https://github.com/chiphuyen/aie-book/blob/main/ToC.md)
- Evaluation decisions: grade outcomes/end state not fixed paths, give partial credit, calibrate LLM judges with humans, allow "Unknown"; pass@k when one success suffices vs pass^k when consistency matters; capability evals start low, regression evals stay ~100% — [Anthropic](https://anthropic.com/engineering/demystifying-evals-for-ai-agents); start with ~20 representative queries — [Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system); Companion: trajectory exact/in-order/precision-recall vs final-response autorater — [ibl.ai summary](https://ibl.ai/blog/google-agents-companion.md)
- Guardrail placement: input guardrails parallel vs blocking (latency vs wasted tokens/side effects); tool guardrails pre/post call — [OpenAI Agents SDK](https://openai.github.io/openai-agents-python/guardrails/); layered defense: LLM + rules + moderation — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Human-in-the-loop: triggers = failure thresholds and high-risk/irreversible actions — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf); Model Spec requires an agreed scope of autonomy defining when to pause for approval — [OpenAI Model Spec](https://model-spec.openai.com/2026-08-18.html); LangGraph interrupts, state inspection/modification — [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview)
- Verification strategy: rules-based (lint), visual feedback (screenshots), LLM-as-judge (less robust, slower) — [Claude blog](https://claude.com/blog/building-agents-with-the-claude-agent-sdk)
- Durable execution / sync vs async: resume from checkpoints rather than restart; async subagents add parallelism but complicate coordination, state consistency, error propagation — [Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system); stateless reducer, launch/pause/resume — [12-factor](https://github.com/humanlayer/12-factor-agents)
- Tool scope decisions: consolidate multi-step ops into one tool vs thin API wrappers; prefix vs suffix namespacing decided by evals — [Anthropic](https://www.anthropic.com/engineering/writing-tools-for-agents); tool overlap, not count, drives splitting — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)

### Inferences
- Canonical interview-style questions the sources themselves pose: "Is this a workflow or an agent, and what is the simplest thing that works?"; "Should orchestration live in code or in the model?"; "When do you split into multiple agents, and manager or handoff?"; "What goes in context up front vs retrieved just-in-time, and how do you survive a long horizon (compaction / notes / subagents)?"; "What is your grader and metric (outcome vs trajectory, pass@k vs pass^k)?"; "Which actions need approval, and what is the agent's scope of autonomy?"; "How does the agent resume after failure?"

### Gaps
- None of the primary sources quantify thresholds for "when to go multi-agent" beyond OpenAI's tool-count anecdote and Anthropic's token multipliers.

## Key Question 4: MCP, A2A, computer use, and agent protocols — core knowledge now?

### Takeaway
MCP is treated as standard infrastructure by every 2025–2026 vendor doc (Anthropic, OpenAI, LangChain), has a dedicated chapter in Hello-Agents and a dedicated DeepLearning.AI course, so it is core; A2A is secondary (one chapter, Linux Foundation governance, framed as complementary to MCP); computer use appears as a tool category and an eval category but not as a standalone chapter in any curriculum.

### Cited Findings
- MCP architecture (spec 2026-07-28): host / client / server; data layer (JSON-RPC 2.0) + transport layer (stdio, Streamable HTTP with OAuth); server primitives tools / resources / prompts; client primitive elicitation; sampling and logging deprecated as of 2026-07-28; stateless per-request `_meta` with `server/discover`; opt-in notifications; Tasks extension for long-running requests — [MCP architecture](https://modelcontextprotocol.io/docs/learn/architecture)
- MCP in vendor stacks: Claude Agent SDK capability list includes MCP — [Claude Code docs](https://code.claude.com/docs/en/agent-sdk/overview); Claude SDK blog lists "MCPs" under Take action — [Claude blog](https://claude.com/blog/building-agents-with-the-claude-agent-sdk); OpenAI SDK has an MCP doc page and tool guardrails for local MCP servers — [OpenAI Agents SDK](https://openai.github.io/openai-agents-python/), [guardrails](https://openai.github.io/openai-agents-python/guardrails/); Anthropic tool-writing guidance assumes prototyping tools as a local MCP server — [Anthropic](https://www.anthropic.com/engineering/writing-tools-for-agents); multi-agent post: a tool-testing agent rewriting MCP tool descriptions cut task time 40% — [Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)
- MCP in curricula: Hello-Agents 第10章 智能体通信协议（MCP、A2A、ANP）and 第13章 case using MCP — [GitHub](https://github.com/datawhalechina/hello-agents); DLAI "MCP: Build Rich-Context AI Apps with Anthropic" full course — [DeepLearning.AI](https://www.deeplearning.ai/short-courses/mcp-build-rich-context-ai-apps-with-anthropic/); Ng's Agentic AI course has an "MCP" lesson in the Tool Use module — [DeepLearning.AI](https://www.deeplearning.ai/courses/agentic-ai/)
- A2A: open standard "enabling communication and interoperability between opaque agentic applications"; developed by Google, donated to Linux Foundation, TSC with AWS, Cisco, Google, IBM, Microsoft, Salesforce, SAP, ServiceNow; v1.0 referenced; MCP = agent-to-tool, A2A = agent-to-agent, complementary — [A2A](https://a2a-protocol.org/latest/); DLAI Box MCP course also covers A2A — [DeepLearning.AI catalog](https://www.deeplearning.ai/short-courses/)
- Computer use: OpenAI guide: "computer-use models" let agents drive legacy systems through UIs — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf); Anthropic evals post treats computer-use agents as a type evaluated in sandboxed environments (WebArena, OSWorld) — [Anthropic](https://anthropic.com/engineering/demystifying-evals-for-ai-agents); DLAI "Building toward Computer Use with Anthropic" course — [DeepLearning.AI catalog](https://www.deeplearning.ai/short-courses/); Berkeley sp25 multimodal/web agents lectures — [sp25](https://llmagents-learning.org/sp25)

### Inferences
- For an interview taxonomy, MCP belongs under "Tools" as the standard transport (host/client/server, primitives, stdio vs HTTP, security/OAuth) and under "Production" for remote-server deployment; A2A/ANP belong in a secondary "multi-agent interoperability" node; computer use belongs under both "Tools" (action modality) and "Evaluation" (sandbox benchmarks).
